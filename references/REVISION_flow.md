# Selected-version revision, safe edits, extraction and translation

## Resolve the source and delta

Use the supplied chunk, exact ID, title or context. Show short candidate differences when ambiguous; never default to latest. Reread each complete selected source before dependent work: get <ID> --json from the selected data_root when accessible; an exact exported prompts file when accessible; otherwise the complete original chunk supplied in a message/attachment. The latter needs no executable helper or Windows path. Verify any present identity against the selected source; use explicit C1/C2 conversation labels when archival IDs are unavailable. Preserve only state/locks actually supplied, never invent missing state. Legacy records may contain version only. Request an inaccessible/missing full source; do not reconstruct verbatim text from a summary.

The same track means the last explicitly selected conversational base, not the latest disk file. Map each donor to role/verified ID or clearly marked conversation label/transferred components. Save final premise, musical map, modes, bans/locks and sources as decisions, not reasoning. An accessible archival base determines parent; pasted-only bases remain explicit source provenance, never a fabricated --parent ID. Restore by rereading after context loss.

Identify what changes and what stays. Preserve exact unaffected fields, not approximations; new INFO/ID/parent change. Emit one Unique version ID (ID), never an additional Version ID (version). Explain and resolve only a real dependency conflict, without full intake.

Reuse the selected composition's known Lyrics/Styles ceilings/detail and selection scope. A local edit or read-only view does not require the first-request questionnaire again; preserve existing options/Exclude in a words-only edit. New explicit size/detail choices replace only affected preferences. For a new composition/redesign with unresolved choices, apply [INTAKE_flow.md](INTAKE_flow.md); do not guess missing legacy state or recompute base settings solely because a new recommendation exists.

| Request | Transfer |
|---|---|
| Put these supplied words in new music | Build around the words; they are not merely a subject for new lyrics |
| Replace words in B | Preserve B's musical cues, Styles/options and voice assignments |
| Words from A, everything else from B | A words verbatim; B form/cues/Styles/options/title, parent B; record donors |
| Entire Lyrics field from A | Transfer A's structure/music cues too |
| New words inspired by A | Original wording using requested subject/devices; not a verbatim claim |

Separate sung/spoken words, intentional syllables and backing responses from production cues. Preserve order/repeats/rhyme endings. Existing user markup informs assignment; unmarked text gets English sections/roles. Formatting/pause changes cannot silently add, rewrite, translate, correct spelling or repeat words. Authorized literary adaptation follows LYRICS_flow and discloses material compromise.

Map donor sections by function before fitting different lengths. Do not truncate the finale or silently adopt the donor's music form. For conflicts in cap, roles, language, bans, verbatim transfer or locks, explain the specific choice needed. Explicitly changing one locked field permits releasing that lock only. Free mode does not cancel verbatim requirements. Preserve base constraints and relevant donor reference identities; do not merge modes/bans arbitrarily.

## Change dependencies

Words/subject -> rhyme/phrasing, keep form/music/Styles/options; language -> phonetics/lang with agreed adaptation only; era/style -> groove/timbres/FX/transitions while preserving words; instrument -> its global and local roles only; voice -> its global/local assignments/options; shortened version -> optional events, keeping subject and locks.

Compare unaffected fields character-for-character and musical Lyrics events by content/order. Use opaque sources and changes in new INFO. Validate full output and save a separate child version when archiving is available; otherwise emit the honest complete context-only result under [PARSER_spec.md](PARSER_spec.md).

## Safer revision after Suno feedback

Accept the reported symptom; ask only a missing detail needed for targeted repair, or perform requested general cleaning. Distinguish user observation from inferred cause and universal claims. Preserve subject/words/defining events. Remove long meta-commands, ambiguous directions, repeat counters and quoted instruction content only after distinguishing intentional backing/hook words.

Move global sound/tempo/delivery to Styles. Keep short familiar headers and essential local cues. Pure instrumental removes unsolicited vocal cues and uses consistent exclusions; manually checking Instrumental toggle may be relevant. An unavailable exact event gets a broader alternative with disclosed precision loss. A safe-revision request narrows tag risk even if maximum detail previously granted high-risk use; unapproved high/unknown notation follows SUNO_TAGS_lib. A new chunk records changes/compromise/risk and parent; no guarantee or claim that old audio was repaired.

Listening feedback records only reported version/symptom/conditions under PERSONAL_spec. One successful or failed generation does not establish universal tag risk. If motif/harmony/groove balance failed, repair relevant relationships under MAIN_THEME/HARMONY/ARRANGEMENT, preserving locks. Do not randomly increase sliders or rewrite every part.

## Read-only text and highlighted views

Default lyrics-only output: one text code block, no parser fields, existing sections separated by blank lines, each performed line separate, essential English singer/delivery cues before blocks and switches. Preserve existing form and vocal events; omit production/FX details. Do not invent a Chorus, role or delivery.

Plain words require an explicit request. Preserve intentional syllables and spoken backing; do not turn nonverbal labels into literal words. A wordless piece has no song words; offer its full musical Lyrics scenario when requested.

Quoted words inside legacy hooks/sections and parenthesized backing require semantic extraction, not deletion of all brackets. Known chord symbols and drum descriptions are production cues; remove them only in minimal/plain/highlight views, preserving complete original lines and role order. Full Lyrics retains them. Translation does not transpose chords or alter drums by itself.

Helper text recognizes a limited vocabulary, extracts known quoted vocal/section words and refuses ambiguous unknowns rather than returning partial text. Do not bypass refusal through blind bracket stripping. Highlighting uses [LYRICS_VIEW_tpl.md](../references/LYRICS_VIEW_tpl.md), including for a requested translation. Views create no new ID/archive and do not modify the source.

## Translation

Default: literary, rhymed, singable. Preserve central meaning, facts, narrator/addressee, action and emotional progression; use natural target-language phrasing/rhyme/stress. Local image paraphrase may help, but no new subject/events. Plan section meaning and fixed images, then target rhyme/phrasing; check chorus and verse separately, internal links, repeats, voice changes and final variation. text_mode governs wording freedom within meaning/rhyme requirements. Mark translation: singable and material compromise in a full chunk.

Literal only when explicitly requested: preserve content/images/stance without distorting meaning for rhyme. Do not promise matching syllables, rhyme or singability. Full output uses translation: literal and relevant limitations. Literal plus compulsory rhyme may conflict; explain rather than claiming both.

Ask only an unclear target language. Translate only selected language inserts/sections. Keep English cues/roles and unaffected title/Styles/options/music. If Styles explicitly names the old lyric language, resolve only that full-output conflict. A separate translation view needs no new ID/archive; a full translated chunk updates lang/translation/ID/parent and saves normally.
