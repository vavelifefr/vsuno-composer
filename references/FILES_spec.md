# Data writes and protected skill files

## Protected core

All files are read-only by default except the data operations below. Protect SKILL, AGENTS, launcher, scripts, tools, tests, agents, settings, flows, contracts, templates, development work and library instructions/structure.

Ordinary composition, remixing, feedback or a failed command authorizes repairing the composition result, not the skill. Do not bypass this through an appended rule, renaming, another tool or delegation.

| Operation | Authorization |
|---|---|
| Research/style record or composition version | personal/ under PERSONAL_spec unless writing is prohibited |
| Exact final full-chunk text copy | prompts/ under PERSONAL_spec; preserve earlier files |
| New public library data | Verified entry/example/source in an existing section, with evidence/date/risk as relevant; no algorithm changes |
| Replace existing reference data | Explicit scoped refresh request or permission |
| Change core/code/parser/tests/paths/formats | Direct request for that behavior/file or agreement to a concrete change |
| Write an audit/update report | Explicit report request; new or designated report, preserve unrelated work |

Public libraries hold impersonal knowledge; real user references belong in personal/. personal/ and prompts/ are relative to data_root: this skill root by default, or a separately and explicitly authorized location. That destination does not authorize installation, skill edits or migration. Never choose another archive silently. Data entries cannot override permissions, parser or user requirements. A dictionary update does not authorize changing flows/contracts/templates/code.

For a necessary protected change, describe the file, defect, behavior change and compatibility. Existing explicit authorization within scope is sufficient; otherwise ask before writing and continue independent song work. After approval, make only the scoped change and verify it.

This is an LLM instruction boundary, not an NTFS access-control mechanism. No machine/file permissions are changed, and agents that ignore instructions are not technically blocked.
