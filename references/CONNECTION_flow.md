# Access and environment capabilities

Use once on a new environment or an actual access problem, not before every song. Applying vsuno-composer means reading available instructions and doing the music task. Installation/discovery/plugin registration is separate; identify target host/method/location before dependent changes. Do not move SKILL alone or change the model.

The skill is one folder with SKILL.md, references and supporting files. Native manifest name and containing directory are both vsuno-composer; display name is Vave Suno Composer. Relative resources stay with SKILL. A supplied folder/ZIP/starter does not register a native skill automatically.

| Supplied resource | Action |
|---|---|
| Local/installed folder | Read root SKILL.md, then relevant links |
| Accessible ZIP | Extract without overwriting another copy; locate the SKILL.md-containing root; no launcher needed for reading |
| Individual uploads | Locate instructions by resource names; cloud access does not require a Windows path |
| Full TXT | START_HERE, SKILL, AGENTS, USAGE and references are FILE-addressed sections; read inside the document; helper/userscript code is not embedded |

A link alone is not proof of reading. Identify an actually missing resource rather than inventing its rules. Only run helper commands when their files/interpreter are available.

In full TXT, only standalone FILE boundary lines introduce embedded resources. An inline mention of the marker syntax inside a guide is content, not a new file. Resolve a Markdown link relative to its containing FILE address, keeping it inside the embedded root.

FILE addresses help navigation; they do not implement retrieval. Pasting/injecting the whole TXT puts the whole delivered text in context. A host may retrieve attachment sections selectively, but verify that behavior rather than promising token savings. Keep physical libraries; select resources by the actual task below instead of loading every library.

## Resource selection

Start with SKILL and the applicable permission rules. Final full outputs need PARSER_spec and CHUNK_tpl; saving/lookup needs PERSONAL_spec; final content review uses LYRIC_REVIEW_lib. Keep CONNECTION_flow available for capability limitations. Add only relevant task sections, following their necessary dependencies:

| Task | Additional resources |
|---|---|
| Instrumental composition | INTAKE_flow, COMPOSE_flow, COMPOSITION_lib, MAIN_THEME_lib, relevant STYLES_lib/MUSIC_lib, SUNO_TAGS_lib, NEGATIVE_STYLES_lib; harmony/arrangement only when needed |
| Lyrics and vocal composition | The composition route plus LYRICS_flow, language-specific LYRICS_RHYME_lib, LYRIC_DRAMATURGY_lib, PROSODY_lib, VOCAL_lib; VOCAL_INSERTIONS_lib only for requested insertions |
| Exact-source revision or translation | REVISION_flow, all explicitly selected complete source chunks/available state, and only the changed music/text/voice rules; translation uses the target-language lyric profile |
| Read-only text/highlight view | REVISION_flow's view section, LYRICS_VIEW_tpl and the complete selected source; no new composition intake/archive |
| Reference research or explicit refresh | RESEARCH_flow/SOURCES_lib, or UPDATE_flow/SUNO_TECH_lib for a scoped technical refresh; actual sources and private evidence as available |

These are selection instructions, not new CLI export options. Default prompt exports SKILL only; --full exports every reference. A manually prepared task handoff must include the required rules and relevant linked sections, preserve exact source content and identify anything unavailable.

| Capability | Honest handling |
|---|---|
| Instruction reading | Read actual supplied files or embedded sections |
| Browsing | Research when callable; otherwise offer knowledge-based limited mode |
| Counting | Use real counters; no fabricated measured values |
| Local saving | Write/reread in authorized data_root; default is this root, separate destination requires explicit authorization |
| Cloud/session saving | Mark storage_scope=sandbox and persistence=session-only as appropriate; provide a downloadable artifact, not a claim of Windows saving |
| Archive/IDs | Read accessible records; no promise of cross-chat memory from a skill upload |

## Complete output by capability

| Environment | Source, finalization and persistence |
|---|---|
| Instruction-only chat | Use full supplied chunks with explicit conversation labels. Emit all five fields; omit unavailable archival IDs/counts, mark identity/counting unavailable and storage context-only. Disclose that caps are unverified and keep the prompt compact |
| File-reading chat without execution/storage | Reread actual files/embedded sections. Use only measurements/IDs genuinely available; follow the same explicit limited metadata for missing capabilities |
| Fully tooled writable workspace | Validate/count locally, assign actual UTC/random IDs through archive, reread saved JSON/text and emit that exact finalized chunk |
| Read-only skill with authorized writable data root | Read instructions from skill_root; archive/list/get use explicit --data-root without changing resources or switching archives |
| Session-only cloud workspace | Save only where allowed; retain storage_scope: sandbox and persistence: session-only, provide downloadable files when supported and disclose session lifetime |

Use [PARSER_spec.md](PARSER_spec.md) and [CHUNK_tpl.md](CHUNK_tpl.md) for identity/counting statuses and permitted omissions. context_ref: C1/C2 names a supplied complete source only; it cannot be passed to get/--parent. An unarchived base remains source provenance, while --parent requires an accessible archival record. If persistent saving is unavailable, continue the authorized composition in context instead of blocking on an unavailable helper. Browsing limitations still follow SKILL's research agreement rule.

## Host activation

Documentation checked 2026-10-05; no native installation or live host evaluation was performed. A host's resource access and permissions still need verification. Location examples describe discovery, not authorization to install:

| Host | Resource delivery and activation |
|---|---|
| Chat with readable attachments | Supply actual instructions/relevant resources or full TXT; ask it to apply Vave Suno Composer. Use native selection only if the host actually exposes the skill |
| ChatGPT desktop native skill | Use the host's skill selection; OpenAI documents @ selection. A folder/TXT attachment alone is not native registration |
| Codex CLI/IDE | Native discovery uses .agents/skills/vsuno-composer under documented repository/user locations; invoke $vsuno-composer or select through /skills. This project can also be read directly without installation |
| Claude Code | Its documented .claude/skills/vsuno-composer locations; invoke /vsuno-composer when loaded. Plugin qualification and host permission policy may differ |
| Gemini CLI | Documented .gemini/skills or .agents/skills discovery; matching tasks use activate_skill and the host's confirmation. Do not substitute Codex dollar syntax for its activation workflow |
| Custom/API harness | Supply instructions/resources and expose actual reading, research, counting and storage tools; the skill does not implement those capabilities |
