# Design lineage and corrected weaknesses

Historical audit examined the legacy SKILL, SUNO-TAGS, MUSIC, GEAR, VOCAL, DAW_MIXING, LINKS, TEMPLATE, SETTINGS and userscript. Ready-made song corpora were not reused as lyric/theme examples. The legacy source remains unchanged.

Retained ideas: six global Styles categories, typed voice parameters, source/role/pattern/articulation distinctions, flexible skeletons, characteristic equipment, official source registry and the five-field parser/userscript.

| Legacy issue | Composer design |
|---|---|
| Large mandatory CORE with many simultaneous rigid rules | Compact entrypoint and selective physical libraries |
| Never/always safety claims and official support mixed with confidence | Separate evidence/estimated risks and high/unknown agreement |
| Inconsistent bracket separator regex versus examples | No inherited pseudo-language; validate the actual parser contract |
| Mostly chains of section names | Section functions, theme/part changes, transitions, plateau and adjustable forms |
| JP-8000 assigned to 1994 despite its 1997 date | Verified chronology and timbre/role fit, no mandatory equipment preset |
| Universal word-count ceiling and rejection of AABB | Natural prosody and phonetic rhyme with varied lengths/schemes |
| Blanket prohibition on common FX | Audible effects allowed without precise automation promises |
| Default extended length, minimum volume, English lyrics and blanket genre Exclude | Independent detail, necessary missing inputs, no minimum and contextual exclusions |
| Reference titles/names/URLs could enter INFO | Private identity/provenance; leak review across the whole chunk |

Accepted extensions: independent music/lyric freedom, conversational or structured intake, private evidence cards, immutable selected versions, targeted remix/safe revision, text/highlight views, default literary/literal-on-request translation, bilingual prosody, rich rhyme/vocal/motif/harmony/arrangement libraries. There is no permanent global repeated-word blacklist.

This English edition preserves those behaviors and library identities while clarifying terminology, shortening repeated explanation and updating internal paths for vsuno-composer. The subsequent authorized portability corrections aligned the manifest/native directory and Codex invocation as vsuno-composer / $vsuno-composer; console launcher remains vsuno.cmd. Rules, explanations and helper/UI text are English; Russian sound examples and native test/user data remain native. Parser fields, state/ID formats and the userscript are preserved.

The later explicitly requested SunoFill adaptation updates this project's userscript to v3.12.0 for grouped INFO. New chunks contain one Unique version ID (ID) plus Parent version (parent); old duplicate metadata stays readable without migration. This scoped change does not rewrite the legacy source described by the historical audit.

Smaller instructions or passing unit tests do not prove better songs or uniform behavior across models. Live LLM and Suno evaluation remains separate. The local launcher adapts an existing Codex CLI without installing a skill, changing PATH or selecting another model.
